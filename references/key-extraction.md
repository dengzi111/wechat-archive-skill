# 微信 4.x 数据库密钥：可行路径、失败记录与风险

> 本文件是实测记录（微信 PC 4.1.13.x / Windows 10），不是理论文档。失败的部分同样重要，能省掉几小时。

## 加密参数（4.x 全线稳定）

| 参数 | 值 |
|------|-----|
| 加密 | AES-256-CBC |
| 认证 | HMAC-SHA512 |
| KDF | PBKDF2-HMAC-SHA512，256000 轮 |
| 页大小 / 保留区 | 4096 / 80（IV 16 + HMAC 64） |
| 每页布局 | `[密文][4016:4032]=IV [4032:4096]=HMAC`；第 1 页前 16 字节是 salt |
| mac_key | `PBKDF2-HMAC-SHA512(enc_key, salt ^ 0x3a, 2 轮, 32)` |

每个 `.db` 有自己的 salt，但共用同一个 account 级 passphrase。**passphrase 跨版本有效**，拿到一次就能长期复用（已验证 4.1.9 拿到的 key 在 4.1.13 上仍然通过 HMAC）。

微信 3.9 完全不同：SHA1 / 64000 轮 / reserve 48，别混用。

## 方法一：管理员 + 开源工具只读扫描（**本次唯一成功的方法**）

微信 4.1.10+ 虽然不再常驻缓存明文 raw key，但 `com.Tencent.WCDB.Config.Cipher` 相关的运行时对象里仍有候选密钥片段，可以在登录状态下只读扫描出来。

```powershell
# 需要用户在场：会弹一次 UAC
Start-Process powershell -Verb RunAs -ArgumentList '-NoProfile','-ExecutionPolicy','Bypass','-Command',
  "python wcdb_key_tool_windows.py --verbose extract --db-dir <db_storage> --output all_keys.json --decrypt"
```

要点：

- **必须提权**。普通权限 `OpenProcess(VM_READ)` 会被拒（错误 5）；工具本身用 `0x0410`，提权后即可读。
- **要读的是实时进程**，所以在微信处于登录、数据库被打开的状态下运行。
- 本机实测：24 个库一次全过（HMAC 校验 100% 通过），密钥缓存到 `all_keys.json`，之后可离线批量解密。
- 只读、不含注入，风险低于 hook/调试器方案，但**仍然属于读进程内存**——见文末风险。

## 方法二：内存扫描 raw key（对 4.0.x ~ 4.1.9 有效）

老版本会把 `x'<64hex enc_key><32hex salt>'` 明文缓存在内存里，扫字符串即可，HMAC 一验就中。4.1.10+ 起该模式被彻底移除（社区对 4.1.10.53 做过 1.3GB 内存 dump + 离线穷举，确认零驻留）。

## 方法三：Frida / x64dbg 断点（技术可行，风险最高）

`Weixin.dll` 里 codec 配置函数入口处，`RCX` 指向的结构前 32 字节即 passphrase。必须 **spawn 模式**在进程启动早期注入，attach 会错过时机。版本更新后 RVA 必变（4.1.12.26 是 `0x3486140`，4.1.13 需重新定位）。**存在 anti-hook 检测，可能导致微信崩溃或错误报告。**

## 方法四：降级安装 ≤4.1.9 提取（风险最低）

在虚拟机里装 4.1.9 登录同一账号 → 用传统内存扫描拿 passphrase → 保存 → 在本机 4.1.13 上用它解密（key 跨版本有效）。零注入风险，代价是要装一次旧版微信。

## 本次实测失败/无效的方向（别再走）

| 尝试 | 结果 |
|------|------|
| 从解密后的数据库里挖 16 字符 ASCII 串当图片 AES key | 283,599 个候选全部失败 |
| 在小文件（config / MMKV / sqlite / key_info.db）暴力搜图片 AES key | 扫了 170MB，0 命中 |
| 图片 XML 里的 `aeskey` 当本地 `.dat` 的 AES key | 12 组全部失败（那是 CDN 下载密钥，不是本地密钥） |
| `msg/attach` 下 28,477 个 `.dat` 硬解 | 目标会话的图片**根本不在 attach 里**（被清理），缓存里另存于 `cache\<年月>\Message\<md5(wxid)>\Bubble\` |
| 全内存暴力试 16 字节密钥（C# 逐字节） | 未能在合理时间内覆盖，且读内存本身触发了风控 |

结论：**图片不要依赖内存密钥**，走 `save_images_ui.ps1` 的 UI 自动化。

## 风险（必须向用户说明）

1. 读微信进程内存属于微信明确防护的行为。本机实测：连续扫描一段时间后，微信弹出「被检测」并要求重新登录。
2. 出现风控提示后：**立即停止所有扫描程序、删除扫描器文件**，短期内不要再让任何第三方工具接触微信。
3. 纯键盘 UI 自动化（`Ctrl+S` 保存图片）与人工操作等价，不会触发风控——这是推荐路径。
